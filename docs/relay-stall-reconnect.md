# 中继慢连接自动重连

> 通用能力：默认开启，不配也不坏；`RELAY_STALL_RECONNECT=0` 可整关闭（行为与旧版一致）。

## 适用场景

用户点播放后**起播正常**（首字节 1–2 秒），但随后速度塌到几十 KB/s、
一直卡；退出重播（全新连接）立刻满速。服务端同期测同文件到 Google
8–9 MB/s，说明不是账号限速、不是带宽问题，而是**某一条上游连接被掐速**。

客户端（SenPlayer 等）遇到这种情况不会自己重连，只会一直卡在那条慢连接上。
本能力让中继层兜底：监测上游出数据速度，塌速时自动建新连接续传，
客户端只看到一条连续的响应流，无感知恢复。

## 行为说明

1. **监测**：转发每块数据时统计"等上游出数据"的时间（`await` 上游吐块的耗时）。
   生成器在 `yield` 处被慢客户端阻塞的时间**不计入**——客户端下行慢不会误触发。
2. **判定**：起播宽限期后（已转发 ≥1MB 或已持续 ≥15s），10 秒窗口内
   "上游字节 / 上游等待秒"持续低于 180KB/s → 塌速。
3. **重连（make-before-break）**：先建新连接，按"已发送字节"发
   `Range: bytes=<offset>-`；确认返回 206 且 Content-Range 起点吻合、
   且读到第一块数据后，才切断旧连接。新连接任何一步失败 → 继续用旧连接
   （慢不断，绝不把"慢"变成"断"）。
4. **无缝续传**：新连接从"已发送 - 一整块"开始（overlap），首块
   （=上一块，已给过客户端）确认后丢弃，后续块逐字节衔接，无缺口无重复。
   客户端看到的状态码/响应头保持初始建连时的值不变。
5. **只对可续传上游启用**：上游带 `Accept-Ranges: bytes` 或 `Content-Range`
   才重连；不支持续传的源站保持原行为（只透传）。

## 三条保护（反风控是铁律：宁可少重连，不可频繁重连）

1. **make-before-break**（见上）：新连失败零影响。
2. **区分"Google 慢"和"用户慢"**：判定只看上游等待时间占比，
   客户端阻塞时间不算上游的账。
3. **多人同时塌速的全局保护**：
   - **令牌桶**：全服每分钟最多 20 次重连尝试，超了本次放弃（排队无意义，
     旧连接还在服务）。
   - **熔断**：60 秒内重连尝试达 10 次 → 更像账号级限速/出口故障而非单连接
     运气差，熔断打开，300 秒冷却期内全服暂停重连，避免扎堆请求加重限速。
     冷却结束自动闭合。
   - **重连换 SA**：每次重连取一个与旧 token 不同的新 SA token（打破亲和），
     分散"单 SA 被掐速"的风险；取 token 是内存命中（预铸），不增加 Google 请求。
   - 单流退避：同流连续重连间隔指数退避（2s 基数，上限 30s）+ 0~1s 随机抖动；
     每条流最多 3 次尝试。
   - 监测逻辑每 chunk 摊还 O(1)，无锁；锁只在触发重连瞬间持有（几次浮点运算），
     不拖慢转发热路径。

## 环境变量（默认即用；非法值 fail-closed 回默认；进程启动时读取，改后需重启）

| 变量 | 默认 | 说明 |
|---|---|---|
| `RELAY_STALL_RECONNECT` | `1` | 总开关；`0`=关闭（旧版行为） |
| `RELAY_STALL_MIN_KBPS` | `180` | 塌速阈值（KB/s） |
| `RELAY_STALL_WINDOW_SEC` | `10` | 判定窗口（秒，按上游等待时间累计） |
| `RELAY_STALL_GRACE_BYTES` | `1048576` | 起播宽限字节数 |
| `RELAY_STALL_GRACE_SEC` | `15` | 起播宽限秒数（与上条任一达到即判定） |
| `RELAY_STALL_MAX_RECONNECTS` | `3` | 每条流最多重连尝试次数（`0`=只监测不重连） |
| `RELAY_STALL_BACKOFF_BASE_SEC` | `2` | 退避基数（秒） |
| `RELAY_STALL_BACKOFF_CAP_SEC` | `30` | 退避上限（秒） |
| `RELAY_STALL_BUDGET_PER_MIN` | `20` | 全局重连预算（次/分钟） |
| `RELAY_STALL_BREAKER_WINDOW_SEC` | `60` | 熔断统计窗口（秒） |
| `RELAY_STALL_BREAKER_THRESHOLD` | `10` | 熔断阈值（窗口内尝试次数） |
| `RELAY_STALL_BREAKER_COOLDOWN_SEC` | `300` | 熔断冷却（秒） |

## 验证

1. 正常播放：日志无 `[relay-reconnect]`（或只有触发记录），播放行为与旧版一致。
2. 塌速时：EA 日志出现
   ```
   [relay-reconnect] 塌速触发重连 <源站> 偏移=<n> 已传=<n>KB 塌速时=<n>KB/s(阈值180) 第1次尝试 换SA=True
   [relay-reconnect] 重连成功 <源站> 新偏移=<n> 第1次
   ```
   客户端不断流、进度不跳、速度恢复。
3. 新连接失败时：`[relay-reconnect] 本次重连未生效，继续旧连接 …：<原因>`，
   播放继续（慢但不断）。
4. 大面积塌速时：`[relay-reconnect] 全局熔断打开：…`（warning），冷却期内
   不再尝试重连。

## 安全说明

- 重连建连走与初始建连**完全同一套**路径：手动跟随重定向、逐跳内网校验、
  跨主机剥凭据、DNS pinning——没有安全降级。
- 重连 Range 只基于本流已发送字节计算，不接受客户端输入，不存在越权读。
- 预算/熔断/退避/抖动四层节流，重连不会变成对 Google 的请求风暴；
  最坏情况（全关保护、阈值拉满）也只是回到"客户端手动重播"的请求量级。
