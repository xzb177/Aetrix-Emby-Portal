# 大本营改版设计方案：手绘营地地图 + 新手引导

> 日期：2026-10-13
> 状态：设计评审 → 实现
> 用户已拍板三件事：① 装备库并入"换装"做双 Tab；② 大本营改版为手绘营地地图；③ 体力槽按团队建议（顶栏常驻 + 报到页完整版）。
> 追加：新手引导作为大本营改版核心验收项。

---

## 一、目标

- 头像菜单 = 老手快捷直达（纯列表），大本营 = 新手导览 + 状态仪表盘，两者分工不重复。
- 新用户第一次进大本营就能看懂"这是哪、我是谁、该先干嘛"。
- 技术小白无障碍：每个设施一句话说清是干嘛的。
- 体力/活力值已确认为同一东西，统一叫"体力"，显示格式统一为 `x/14`。

---

## 二、改动 1：换装双 Tab（装备库并入）

### 现状
- `OutfitView.vue` 只有"营地天色"（主题换肤）一个 Tab。
- 装备库代码在 bundle 里但无路由入口（死代码悬空）。

### 方案
- `/game/outfit` 保留一个入口，页内顶部加 v4 纸片风格牛皮纸标签：
  - Tab 1「穿搭」：现有营地天色试穿功能原样保留。
  - Tab 2「装备库」：新 Tab，首版内容 = 装备收藏展示（空状态先给"还没有装备，去探险攒一件"的纸片空态 + 跳转引导）。
- Tab 切换不跳路由（内部 state），头像菜单/大本营仍只引 `/game/outfit` 一个入口。
- 死代码闭环：装备库从此有入口，不再悬空。

### 验收
- 点换装进页，两个牛皮纸标签可切换；刷新后停留在上次 Tab（可选 localStorage 记忆，低成本就做）。

## 三、改动 2：大本营改版（手绘营地地图 + 新手引导）★核心

### 3.1 页面结构（/game）

```
┌─────────────────────────────┐
│ 印章：探险家 · 大本营        │  ← v4-loghead 保留
│ 🏕️ 探险日志                  │
│ 一句话状态：今日体力 12/14 ·  │  ← 新增"今日状态条"（替代体力槽组件）
│   已报到✓ / 待报到           │
├─────────────────────────────┤
│ 🧭 新手引导卡（首次进入展示） │  ← 新增，可跳过，localStorage 记忆
│  向导纸片人带路：             │
│  ① 先去报到 → ② 领体力       │
│  → ③ 逛一圈设施              │
│  [开始逛逛] [跳过]           │
├─────────────────────────────┤
│ 每日必做                     │  ← 分组标题（v4-sec-title）
│  [📋每日报到 ✓] [🗺️探险预告]  │
│ 社交                         │
│  [📡求救信号] [🕊️信鸽 ·3封]   │  ← 活卡片：未读数
│ 资产                         │
│  [📒能量账本] [🧾补给记录]     │
│ 形象                         │
│  [🤝结伴同行] [🧭向导] [👕换装]│
└─────────────────────────────┘
```

### 3.2 关键设计点（用户拍板：手绘营地地图风格）

1. **营地地图板**：整块设施区做成一张"营地地图"纸板——纸纹底 + 虚线小径 +
   手绘风分区牌。设施不再是竖排列表，而是按营地位置摆放的"帐篷/小屋"标记卡，
   点标记直接进。CSS 实现（定位 + 虚线边框 + 纸纹），不引入 SVG 美术资源，
   成本可控但有地图感。
   分区（营地语义 + 意图分组二合一）：
   - ⛺ 营地门口（每日必做）：每日报到 📋、探险预告 🗺️
   - 📡 传讯高地（社交）：求救信号、信鸽 🕊️、结伴同行 🤝
   - 📒 账房小屋（资产）：能量账本、补给记录 🧾
   - 🎪 生活营区（形象）：向导 🧭、换装 👕
   分区归属写进 `config/game.ts` 注册表 `group` 字段（见下）。

2. **今日状态条**：放在地图板上方，一句话，白话。例：
   - `今日体力 12/14 · 已报到✓，出发吧！`
   - `今日体力 14/14 · 还没报到，点我去盖章 →`（可点，跳 `/game/checkin`）
   - 数据：`vitalityApi.status()` + `checkinApi.status()`，失败静默降级（只显示静态文案）。
3. **新手引导卡**：
   - 触发：`localStorage['camp_onboarded']` 为空且已登录 → 展示。
   - 内容：纸片风格向导角色（🧭 复用向导设施 icon，不新增美术资源）+ 3 步白话引导。
   - 按钮：`[跟着向导逛逛]`（跳 `/game/checkin` 开始第一步）`[我自己逛]`（跳过，写 localStorage）。
   - 验收：首次进显示、跳过后不再显示、清 localStorage 可重现。
4. **活卡片**（状态徽标，非全量实时）：
   - 每日报到卡：`checked_today` → 显示 `✓今日已报到` / `待报到`。
   - 信鸽卡：`/api/user/messages/unread-count` → `·3封未读`（0 则不显示）。
   - 其他卡：静态介绍。失败全部静默降级为静态卡，不 blocking。
5. **设施分组**（写进 `config/game.ts` 注册表 `group` 字段）：
   - `daily` 每日必做：checkin（每日报到）、calendar（探险预告）
   - `social` 社交：signal（求救信号）、pigeon（信鸽）、companion（结伴同行）
   - `asset` 资产：ledger（能量账本）、supply（补给记录）
   - `style` 形象：guide（向导）、outfit（换装）
   - companion 放社交（组队是社交行为）。
6. **设施注册表升级**（`GameFacility` 加字段，向后兼容）：
   ```ts
   group: 'daily' | 'social' | 'asset' | 'style'
   order: number            // 组内排序
   enabled: boolean         // 总开关（默认 true）
   guideTip?: string        // 新手引导里的一句话（小白版介绍，可选）
   ```
   头像菜单、大本营、路由继续读同一数组——"加设施=改一行配置"。
7. **小白版介绍**：现有 `desc` 已够白话，逐条复核，不拗口就不改；`guideTip` 只在引导卡里用更短的版本（不写则 fallback `desc`）。

### 3.3 不做的
- 不引入 SVG/图片美术资源：地图感用 CSS（纸纹底 + 虚线小径 + 手绘风分区牌）实现。
- 体力槽组件从大本营顶部撤下（今日状态条替代，避免重复）。
- 不动路由结构。

### 验收（核心项）
- [ ] 新用户首次进 /game 看到向导引导卡，可跳过，跳过后不再出现。
- [ ] 今日状态条文案正确（报到前后两种状态都测）。
- [ ] 活卡片状态正确（报到✓、未读数），API 失败时降级为静态卡。
- [ ] 设施按 4 组展示，顺序与头像菜单一致、名字一字不差。
- [ ] v4 纸片风格一致，无深色旧样式残留。

## 四、改动 3：体力槽（顶栏常驻）

### 方案
- 顶栏活力值徽章：显示格式从纯数字 `14` 改为 `14/14`（与体力条统一）。
- 点击徽章 → `/game/checkin`（原 `/game`）。
- 积分徽章点击 → `/game/ledger` 能量账本（原 `/game`）。
- 报到页保留完整版 `StaminaBar`。
- 大本营顶部 `StaminaBar` 撤下（今日状态条替代）。

### 验收
- [ ] 顶栏显示 `⚡14/14`，点击进报到页。
- [ ] 积分徽章点击进能量账本。
- [ ] 大本营无体力槽组件、无幽灵间隙。

## 七、附：首页评估（团队意见，用户拍板"按团队意见来"）

**事实**：首页是"仪表盘+服务台"口径——资产、事项、进度齐全，但缺"家的温度"：
全站"探险营地"世界观在首页零体现。

**加（2 项，零请求、<50 行）：**
1. **营地晨间便签**：Hero 下方一张小纸片条，每天一句随机营地文案
   （本地静态数组 + 日期种子，零请求）。每天打开"今天不一样"，配合"常来"目标。
2. **时段问候升级**：Hero 问候改为营地味时段语（"夜深了，营地篝火还亮着"），
   改 greeting 计算逻辑，一行代码的事。

**不加**：设施入口（三处重复；首页"功能入口统一由顶栏承担"已有定论）、
带请求的新数据卡（零新请求纪律）、积分卡/继续观看二度扩展。

**验收**：便签每天文案不同（按日期种子可验证）；问候文案有时段+营地味；
无新增 API 请求；v4 纸片风格一致。
