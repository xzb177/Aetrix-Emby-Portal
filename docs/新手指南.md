# 新手指南：从零跑起来

这份文档假设你**没用过这个项目**，也没部署过类似系统。跟着做就能跑起来。

---

## 第一部分：这是什么东西？

### 一句话

**把「自己的影视服务器 + 会员网站」一次装好，不用再单独装 Emby。**

### 打个比方

想象你要开一个视频网站，需要这些东西：

| 你想要的 | 相当于 |
|---|---|
| 片库（电影、剧集放在硬盘里） | 你的网盘 / NAS |
| 片库的信息页（海报、简介、分类） | 视频网站的详情页 |
| 让 App 看到片库并播放 | 视频网站的播放器接口 |
| 用户注册登录、会员付费 | 视频网站的会员系统 |
| 管理员管理这一切 | 视频网站的后台 |

**Aetrix 把上面这些全做了，而且伪装成一个 Emby 服务器。**

### 为什么说「伪装成 Emby」

因为 Infuse、Forward、SenPlayer 这些播放器 App 只认 Emby 的接口。Aetrix 内部自己实现了这套接口，
所以你**不用装官方 Emby**，直接让这些 App 连上 Aetrix 就能播片。

**好处**：界面、会员、支付全是你自己的，不用被官方 Emby 的限制绑住。

### 名字怎么来的（不影响使用，知道了就行）

- `Aetrix` = Aether（串流）+ Matrix（多台服务器组网）
- 全项目里的 **EM** 和 **EA** 是两个角色：
  - **EM** = 面板。网页（用户端 + 管理后台）、片库扫描、会员系统
  - **EA** = 出流。真正把视频字节传出去（直链或中继，服务端不转码）
- 小机器可以让它们待在一起（默认就是这样）；机器好、想专门出流，就把 EA 拆到另一台

## 第二部分：需要准备什么

### 1. 一台服务器

| 项目 | 建议 |
|---|---|
| CPU | 2 核起（服务端不转码，CPU 主要花在扫描和中继出流上） |
| 内存 | 4GB 起 |
| 硬盘 | 存片的地方另算，系统盘 20GB 起 |
| 系统 | Linux（Ubuntu / Debian / CentOS 都行） |

### 2. 装好 Docker

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
```

装完验证：

```bash
docker --version
docker compose version   # 没有这条命令说明版本太老，见下方「常见问题」
```

### 3. 准备一个固定密钥（**最重要，别跳过**）

这个密钥用来加密登录凭证、签名 JWT。**它必须一直不变**——换了密钥，所有用户都要重新登录。

生成一个：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

复制输出的那串字符，下一步要用。

## 第三部分：开始安装

### 1. 拉代码

```bash
git clone https://github.com/xzb177/Aetrix-Emby-Portal.git
cd Aetrix-Emby-Portal
```

不会用 git？直接在 GitHub 页面点 **Code → Download ZIP**，解压后进入文件夹。

### 2. 准备配置文件

```bash
cp env.example .env
```

这一步会生成一个 `.env` 文件，**里面每一项都有注释说明**。

### 3. 填这几样

用文本编辑器打开 `.env`（服务器上可以用 `nano .env`）：

**① 填密钥**

找到 `SECRET_KEY=` 这行（默认是空的），把第二步生成的字符串填进去：

```ini
SECRET_KEY=你刚才生成的那串字符
```

> ⚠️ 填错或者留空，服务会**拒绝启动**并给出提示。这是有意的——空密钥等于没有锁。

**② 填域名（如果还没有域名，可以先跳过）**

```ini
EMBY_PUBLIC_URL=https://你的域名
```

暂时没有域名？先不管，等有了再回来改。改完记得重启服务。

**③ 挂上你的片库目录**

```ini
MEDIA_ROOT=/你的影视文件夹路径
```

比如你的片子放在 `/mnt/nas/movies`，就填这个。Docker 只能看到**宿主机上的真实路径**，
填错了会扫不到片。

**④ 改数据库密码**

找到 `POSTGRES_PASSWORD=`。自建编排用它连接 PostgreSQL。示例文件里的值只为了能启动，公开部署前换成一长串随机字符（生成方法和上面的密钥一样）。

### 4. 启动

只需要接口、用播放器直连时：

```bash
bash scripts/deploy.sh
```

第一次会比较慢（要下载依赖、构建镜像），耐心等。脚本结束时会自动检查服务是否健康。

**想先看看它打算做什么**（不实际执行）：

```bash
bash scripts/deploy.sh --dry-run
```

还要浏览器里的用户端和管理后台时，不要用上面的脚本，改用：

```bash
docker compose -f docker-compose.yml -f docker-compose.frontend.yml build --pull
docker compose -f docker-compose.yml -f docker-compose.frontend.yml up -d
```

两套命令不要交替执行。脚本带 `--remove-orphans`，会删掉网页容器 `aetrix-web`。

### 5. 确认跑起来了

```bash
curl http://127.0.0.1:8000/api/health
```

JSON 里的 `status` 为 `healthy` 即面板正常。

管理后台不在 8000 端口。起了网页容器之后打开 `http://<你的服务器IP>:8081/admin/`。只跑了 `deploy.sh` 时没有这个页面，用下面的命令创建管理员。

## 第四部分：第一次配置

### 1. 创建管理员

```bash
docker compose exec aetrix-api python scripts/create_admin.py
```

不带参数会创建或升级用户 `admin` 并打印随机密码。指定账号用 `-u` 和 `-p`。网页向导可用时，也可以在 `http://<你的服务器IP>:8081/admin/` 里完成第一次初始化。

### 2. 登录后台，加片库

浏览器进 `http://<你的服务器IP>:8081/admin/`，用刚才的账号登录。只跑了 `deploy.sh`、没有网页容器时，这个地址打不开。

**媒体库 → 添加媒体库**：
- 填个名字（比如「电影」）
- 填容器内能看到片库的路径，通常是 `/media/电影`

### 3. 扫描

在媒体库页面点「扫描」。Aetrix 会：
- 递归遍历目录
- 从文件名认出电影/剧集/季/集（`S01E02`、`1x02`、`第3集` 都能认）
- 找到外挂字幕

扫描完成，片库就有内容了。

### 4. 让播放器连上

在 Infuse、SenPlayer 或 Emby 官方 App 里添加服务器，地址填：

```text
http://<你的服务器IP>:8000
```

不要填 `:8081`，不要在末尾加 `/emby`。用户名和密码用门户账号。用户账号在用户端注册，或由管理员在后台创建。

## 第五部分：日常维护

### 更新到新版本

先备份 PostgreSQL：

```bash
bash scripts/backup_db.sh
```

只使用 `deploy.sh` 这条路线时：

```bash
bash scripts/update.sh
```

`update.sh` 发现没有 SQLite 文件会跳过备份并继续更新，所以不能依赖它保护 PostgreSQL。

使用了网页编排时，不要跑 `update.sh`（它会摘掉网页容器）：

```bash
git pull --ff-only
docker compose -f docker-compose.yml -f docker-compose.frontend.yml build --pull
docker compose -f docker-compose.yml -f docker-compose.frontend.yml up -d
```

### 备份

`scripts/backup_db.sh` 把转储写到仓库目录 `backups/aetrix-<时间戳>.sql.gz`，默认保留 14 天。

程序内的每日备份由 worker 调度，默认时刻 03:00、保留 7 天。PostgreSQL 时文件在容器 `/var/backups/aetrix`，格式与上面的 `.sql.gz` 不同。更新前仍以 `backup_db.sh` 为准。

### 看日志

```bash
docker logs -f aetrix-api      # 面板 API
docker logs -f aetrix-worker   # 后台任务（扫描、补图等）
docker logs -f aetrix-ea       # 出流、字幕
```

### 重启

```bash
docker compose restart
```

## 常见问题

<details>
<summary><b>没有 <code>docker compose</code> 这条命令</b></summary>

Docker 太老，只支持 `docker-compose`（带横线）。

```bash
# 升级 compose 插件
sudo apt-get install docker-compose-plugin
```

或临时用旧命令：`docker-compose up -d`。
</details>

<details>
<summary><b>启动时报「SECRET_KEY 未设置」</b></summary>

`.env` 里 `SECRET_KEY=` 还是空的。回到第三部分第 3 步填上。
</details>

<details>
<summary><b>扫描不到片</b></summary>

九成是路径问题。按顺序检查：

1. `.env` 里的 `MEDIA_ROOT` 填的是**宿主机**路径，不是容器内路径
2. 确认 Docker 真的能看到那个目录：
   ```bash
   docker exec aetrix-api ls /media
   ```
   如果这里看不到，说明挂载没生效

3. 片库设置里填的路径应该是**容器内**路径（通常是 `/media/xxx`）
</details>

<details>
<summary><b>端口被占用，起不来</b></summary>

自建编排不读 `.env` 里的 `PORT`。改端口应改 `docker-compose.yml` 里 `aetrix-api` 的 `ports`，以及 `docker-compose.frontend.yml` 里的 `8081:80`。改完重新启动，访问地址的端口也要跟着改。
</details>

<details>
<summary><b>内存不够，容器被杀掉</b></summary>

Docker 默认可能限制内存。编辑 `docker-compose.yml` 或加到 `.env`，给服务留够内存。
扫描比较吃内存，建议至少 4GB。
</details>

<details>
<summary><b>想加个新片库，怎么加？</b></summary>

后台 → 媒体库 → 添加。也可以在 `.env` 里挂更多目录：

```ini
MEDIA_ROOT=/mnt/nas
```

挂整个上层目录，然后在里面给每个子目录建一个媒体库。
</details>

<details>
<summary><b>数据存在哪？会不会丢？</b></summary>

PostgreSQL 在命名卷 `postgres_data`。海报、缩略图等缓存在卷 `aetrix_data`（容器内 `/data`），那里不是数据库。`docker compose down -v` 会删除这些卷。卷不会自动拷到你的电脑，更新前用上面的 `scripts/backup_db.sh`。
</details>

<details>
<summary><b>怎么升级到 PostgreSQL？</b></summary>

v2.42.0 起默认就是 PostgreSQL，用 Docker Compose 部署会自动配好，不用管。

老部署想切换，参考 [部署文档](deploy-docker.md)。
</details>
